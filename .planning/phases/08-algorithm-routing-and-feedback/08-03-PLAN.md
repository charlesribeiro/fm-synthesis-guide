**Routing-message contract (resolved):** Plan 08-01's `applyRoutingToWorklet` posted all three
messages on every apply. This plan selects Pitfall 5 message separation instead:
`applyInstrumentStateToWorklet` (shared by the constructor `effect()` and the synchronous
`setAlgorithm` / `setFeedback` / `updateOperatorLevel` re-apply path) posts only the message
kinds whose inputs actually changed against `lastApplied*`. Unchanged operator or feedback
snapshots are not resent. That choice is authoritative for this plan's must-haves, Task 3, and
tests; it supersedes 08-01's always-post-three body.

<objective>
Harden the boundary the routed engine depends on, and make the live parameter
and algorithm paths real end to end.

Purpose: Plan 08-01 made the routed path work; this plan makes it hold up. Three
new message kinds widened the one surface that stands between an arbitrary
structured-clone payload and a per-sample recurrence, and the engine's three
interface methods went from validated no-ops to real writes that Playground and
the lessons now depend on.

Output: A hostile-payload matrix for every new message kind, parity between the
real built bundle and the kernel proved in Vitest, and the held-note re-patch
and parameter-propagation behaviours asserted over the fake node boundary.
</objective>
