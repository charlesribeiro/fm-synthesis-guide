**2. `src/app/domain/dx7/dsp/graph-router.ts` — NEW (D-08, D-09, D-15, D-16).**
Open with the domain-purity header comment convention every sibling in `dsp/` uses (zero Angular imports, DOMAIN-04-enforced, original-implementation disclaimer), and state that this is the first module in `dsp/` deliberately allowed to bridge the canonical dataset into kernel configuration — mirroring and inverting `additive-fixture.ts`'s header, which documents why it does *not*.

Export `DESCENDING_OPERATOR_IDS` as a frozen `readonly OperatorId[]` built once from `[...OPERATOR_IDS].reverse()`. Export `interface RoutingConfig { readonly connections: readonly OperatorConnection[]; readonly carriers: readonly OperatorId[] }` reusing the `OperatorConnection` type from `patch-plan.ts`. Export `buildRoutingConfig(algorithm: AlgorithmDefinition): RoutingConfig` as the single translation entry point, delegating to the already-tested connection planner in `patch-plan.ts` and the carrier derivation in `derive-role.ts` — this function is the only place in the phase that performs that derivation.

Export `class GraphRouter` with `constructor(sampleRate: number, blockSize: number)`. Validate `blockSize` with the same reject-before-allocate `RangeError` shape `additive-fixture.ts` uses. Allocate everything once in the constructor and never inside `render`: six persistent `PhaseModulatedOperator` instances stored in an array of length 7 indexed by operator id (index 0 unused, so id lookup is a plain index, not a `Map`), one `Float32Array(blockSize)` per operator to hold that operator's rendered block, one shared `Float32Array(blockSize)` modulation accumulator, and three `Float64Array(7)` tables for per-operator frequency, per-operator modulation index and per-operator carrier amplitude.

Public setters: `setRouting(config: RoutingConfig)`, `setOperatorParameters(operators: OperatorParameterSet)`, `setFeedbackLevel(level: number)`, `setNoteFrequencyHz(noteFrequencyHz: number)`. Each stores its input and then calls one private `recomputeDerivedValues()`; no derived value is ever recomputed inside `render`. `setRouting` additionally caches the feedback operator id read from the config's own `isFeedback` flag (never re-derived from algorithm data here), and calls `resetPhase()` on all six operators so no feedback history or phase survives a topology change (Pitfall 4).

`recomputeDerivedValues()` computes, per operator id: the frequency via `operatorFrequencyHz(parameters, noteFrequencyHz)` from `value-conversion.ts` (D-15); the enabled multiplier as `1` when `enabled`, else `0`; the carrier amplitude as `outputLevelToAmplitude(outputLevel)` times the enabled multiplier (D-16); and the modulation index as `outputLevelToModulationDepthHz(outputLevel, frequency) / frequency` times the enabled multiplier. That division is load-bearing and must be written explicitly: `outputLevelToModulationDepthHz` returns a peak frequency deviation in Hz, the unit Phase 5's oscillator engine needed, whereas this kernel adds its modulation input to the phase argument in radians — using the Hz value unmodified would silently scale the effective index by the modulator's own frequency. The feedback index is `feedbackLevelToDepthHz(level, feedbackOperatorFrequency) / feedbackOperatorFrequency` times the feedback operator's enabled multiplier (D-09). Whenever a frequency is not finite or is not greater than zero, sanitise it to `0` before calling `setFrequencyHz` (which would otherwise throw on the render thread) and set that operator's modulation index — and, where applicable, the feedback index — to `0`. Push each sanitised frequency into the corresponding operator via `setFrequencyHz`.

`render(output: Float32Array): void` rejects a mismatched `output.length` with the same `RangeError` shape `additive-fixture.ts` uses, then walks `DESCENDING_OPERATOR_IDS`. For each id: `fill(0)` the shared modulation accumulator; for every connection whose `to` equals that id and whose `isFeedback` is false, accumulate `sourceBlock[i] * modulationIndex[connection.from]` into the accumulator (the source's block is already rendered because the higher-modulates-lower invariant guarantees `from > to` for every non-self-loop edge); then render the operator's own block, using `renderWithFeedback(block, feedbackIndex, accumulator)` when that id is the cached feedback operator and `render(block, accumulator)` otherwise. This branch must always pass the accumulator through in the feedback case as well — never treat "is the feedback operator" and "has incoming edges" as mutually exclusive.

Finally: `output.fill(0)`, accumulate each carrier's block times its carrier amplitude, multiply every sample by `MASTER_GAIN` imported from `value-conversion.ts`, and hard-clamp each sample with `Math.min(1, Math.max(-1, sample))`. The `MASTER_GAIN` factor belongs here rather than only on a downstream gain node for two reasons, and both must be recorded in a doc comment: the Vitest bounded-output proof in plan 08-02 never touches Web Audio, so nothing downstream of this method can be relied on to bound the signal; and without it a six-carrier algorithm's raw sum reaches six, so a bound applied to the unnormalised sum would clip ordinary playing rather than acting as a safety ceiling. This scaling preserves Phase 5's already-approved loudness exactly: six unity carriers reach one, not six. Apply no other output shaping of any kind — no smooth transfer curve, no averaging on the self-feedback path, no soft ceiling. The bound is the only limiter, per D-07/D-08.
