<design_decisions>
**Group labels live in the component, group membership lives in the dataset.**
The four human-facing strings ("Additive stacks", "Tree and branch", "Rooting", "Parallel" plus
their one-line descriptions) are presentation copy and stay in the component, keyed by
`TeachingTag`. Which algorithms are in each group is read by filtering `ALGORITHMS` on
`teachingTags`. The range label ("Algorithms 1–6") is computed from the filtered ids, not typed in —
the existing spec asserts those four exact strings, and deriving them keeps that assertion true
while removing the possibility of a stale label.

**Card shape (D-03, RESEARCH Pitfall 3).**
`AlgorithmDefinition.name` is a full-sentence topology description, not a short title. The card
heading is `Algorithm {id}`; the dataset name is supporting body text beneath it, allowed to wrap
across several lines. No thumbnail SVG is rendered — D-03 forbids it and 32 diagrams on one page
would be the expensive thing it forbids them for.

**Nested lists, one link per item.**
Each group card holds a nested `<ul>` labelled by the group heading, and each algorithm is a single
anchor. One interactive element per item keeps keyboard traversal predictable and avoids a nested
control inside a link.
</design_decisions>
