<design_decisions>
Decisions this plan makes inside CONTEXT.md's "Claude's Discretion" area. Implement these as
written rather than re-deciding them.

**Directory — `src/app/domain/dx7/diagram/` (new).**
Keeps the 32 layout-hint records directorially separate from the 32 graph-truth records in
`models/algorithms.ts`, which is D-05's "layout layer separate from synthesis truth". The path is
still under `src/app/domain/**`, so the DOMAIN-04 domain-purity ESLint rule
(`eslint.config.js`, the `src/app/domain/**/*.ts` block) applies automatically — no Angular imports,
value or type-only.

**Shared canvas grid (D-06, D-07) — a fixed row/column ladder, not free-form coordinates.**
Every operator position must be a point on this grid:
- `DIAGRAM_VIEWBOX = '0 0 420 300'`, `NODE_RADIUS = 18`
- `ROW_Y = [56, 104, 152, 200, 248]` — index 0 is the topmost modulator band, index 4 is the carrier band
- `CARRIER_ROW_Y = 248` (identical to `ROW_Y[4]`)
- `COLUMN_X = [40, 105, 170, 235, 300, 365]`
- `OUTPUT_BUS_Y = 280`
Five rows is exactly enough: the deepest modulation chain in the dataset is five operators
(Algorithm 7); this was measured against `ALGORITHMS`, not assumed. Six columns cover Algorithm 32's
six side-by-side carriers. The grid turns D-06 into two machine-checkable invariants that Plan 02
enforces over all 32 records: every carrier sits at `CARRIER_ROW_Y`, and for every modulation edge
the source operator's `y` is strictly less than the target's.

**Route param source — injected `ActivatedRoute` + `toSignal(route.paramMap)`, not `withComponentInputBinding()`.**
This closes RESEARCH.md Open Question 1 and Pitfall 1 at once, and also fixes a second problem
RESEARCH.md did not raise: Plan 04's prev/next links navigate `/algorithms/1` -> `/algorithms/2` on
the *same* route, so Angular reuses the component and a `snapshot`-only read would go stale.
`toSignal(this.route.paramMap, { initialValue: this.route.snapshot.paramMap })` gives a correct
first value on a cold deep link *and* updates on same-route navigation, using the sanctioned
`@angular/core/rxjs-interop` helper rather than a manual subscription (CLAUDE.md). `app.config.ts`
is deliberately left unmodified.

**Selection state shape (D-10).**
A private `signal<OperatorId | null>(null)` inside `AlgorithmDiagram`, exposed as `.asReadonly()`,
mutated only by a `selectNode` method — the same private-writable/public-readonly shape as
`MotionPreference` and `InstrumentState`. It is kept OUT of the view model so a selection change
never rebuilds the node/edge arrays (RESEARCH.md Pitfall 4). Selecting a node also highlights its
connected edges (the discretionary half of D-10 — answered yes), signalled by stroke width as well
as color so the highlight is not color-only either.

**Uniform edge styling.**
Modulation edges all render with the same stroke weight this phase. Edge thickness reflecting live
modulation amount needs `InstrumentState`, which D-10 deliberately keeps out of this component;
that binding belongs to whichever phase first wires live state into the diagram. Nothing here
blocks it: the view model already carries a per-edge object that can gain an intensity field.

**Accessibility contract.**
`<svg>` (no `role="img"`) with `<title>` (short) and `<desc>` (the full D-12 enumeration), both
referenced from `aria-labelledby`, so interactive operator `role="button"` nodes remain exposed to
assistive technology. All generated DOM ids are namespaced by algorithm id **and** a stable
per-component-instance suffix
(`algorithm-{id}-diagram-title-{instance}`, `-desc-`, `-arrow-`) so a second instance of the same
algorithm on the page cannot collide — this includes the `<marker>` id, which is document-global in
SVG just as element ids are. Apply the same suffix consistently to `aria-labelledby` references and
`marker-end` bindings. A visually hidden `role="status"` region beside the SVG announces the current
node selection.
</design_decisions>
