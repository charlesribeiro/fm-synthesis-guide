<design_decisions>
**Authoring procedure for the 30 remaining records (an authoring aid, not shipped code).**
D-05 rejects computing layout at render time; it does not require guessing coordinates. Derive each
record once, at authoring time, with this repeatable procedure, then commit the resulting numbers as
static data. No layout function ships.

For each algorithm:
1. Take its modulation edges — every edge where `from` differs from `to`. The self-loop is ignored
   for placement; it decorates a node that is already placed.
2. Give each operator a depth: a carrier has depth 1; any other operator's depth is one more than
   the greatest depth among the operators it modulates.
3. Row index is `5 - depth`, so depth 1 lands on `ROW_Y[4]` (`CARRIER_ROW_Y`) and the deepest
   modulator in the dataset, at depth 5, lands on `ROW_Y[0]`.
4. Split the operators into connected components of the modulation graph. Order the components by
   their lowest carrier id ascending; that becomes their left-to-right order.
5. Give every operator in a component the column of that component's carrier. When a component has
   more than one carrier, or when two operators in one component would land on the same row and
   column, spread them across adjacent columns so no two operators share a coordinate.
6. Centre the columns actually used: if an algorithm uses `k` columns, start at `COLUMN_X` index
   `Math.floor((6 - k) / 2)`.

Step 2's depth rule is what makes the D-06 downward-flow invariant true by construction. The
measured maximum depth across the dataset is 5, so `ROW_Y`'s five bands are exactly sufficient.

**The clearance invariant replaces part of the manual "reads cleanly" judgment.**
`04-VALIDATION.md` lists layout legibility as manual-only. Two thirds of it are computable from the
coordinates alone — coincident nodes, and edges passing through unrelated nodes — so this plan
asserts both mechanically and leaves only aesthetic balance to the Plan 05 checkpoint.
</design_decisions>
