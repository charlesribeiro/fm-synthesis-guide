<design_decisions>
**Pager boundaries render as absence, not as a disabled control.**
At algorithm 1 the previous link is not rendered at all; at algorithm 32 the next link is not
rendered. A disabled anchor is not a real control and a wrapping pager would imply the 32 algorithms
form a cycle, which is exactly the wrong mental model for a numbered teaching sequence. The pager
container keeps a fixed two-slot layout so the page does not shift between the ends and the middle.

**Bounds come from the domain constants.**
`MIN_ALGORITHM_ID` and `MAX_ALGORITHM_ID` already exist in `models/algorithm.ts` and already back
`isAlgorithmId`. The pager reads them rather than writing 1 and 32, so the pager cannot disagree
with the validator that guards the same range.

**Not-found is a state of this route, not a redirect.**
`/algorithms/99` stays at `/algorithms/99` and explains itself. `04-RESEARCH.md` Open Question 2
recommended this; the alternative — a `redirectTo` guard — turns a mistyped address into a silent
bounce that hides broken links from whoever wrote them.

**Same-route navigation correctness.**
Prev/next navigate within the same route, so Angular reuses the component instance. Plan 01 already
chose `toSignal(route.paramMap, { initialValue: route.snapshot.paramMap })` for exactly this reason;
this plan adds the test that proves it, because a `snapshot`-only read passes every single-navigation
test and fails the first time a user clicks "next".
</design_decisions>
