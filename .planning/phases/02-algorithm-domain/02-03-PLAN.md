## DOMAIN-02's five rejection classes, mapped to concrete rules

DOMAIN-02 names five things validation must reject. Two of them need an explicit reading before
they can be implemented, so the mapping is fixed here rather than left to the executor:

| DOMAIN-02 phrase | Concrete rule(s) | Level |
|---|---|---|
| impossible IDs | `id` fails `isAlgorithmId`; any `edge.from` or `edge.to` fails `isOperatorId` | per-algorithm |
| invalid edges | a non-self-loop edge with `from <= to`; the same edge declared twice; an entry that fails `isModulationEdge` | per-algorithm |
| malformed feedback declarations | more than one self-loop edge (D-04) | per-algorithm |
| missing operators | zero carriers — the only observable form this can take, see below | per-algorithm |
| duplicate algorithm IDs | two entries sharing an `id` | set |

**"Missing operators" needs interpretation.** Role derivation is total over `OPERATOR_IDS`, so
every algorithm always accounts for all six operators by construction; and Algorithm 32 declares
no inter-operator edges at all, so "every operator appears in some edge" would wrongly reject the
one genuinely edge-free algorithm in the dataset. The only observable failure is an algorithm
with **zero carriers**, which means every operator modulates another one and the sound reaches no
output. Reject that. At the set level, the companion rule is that the 32 ids cover 1..32 exactly.

**Acyclicity does not need its own algorithm.** RESEARCH.md § Don't Hand-Roll suggests a Kahn's
topological sort to prove the non-feedback edges form a DAG. The higher-modulates-lower rule makes
that redundant: if every non-self-loop edge strictly decreases the operator number, following any
path strictly decreases a bounded integer, so no cycle can exist. Assert `from > to` and skip the
sort — do not add a graph-traversal helper this phase does not need.

**D-04's "feedback edge with `from !== to` mislabeled as feedback" is unrepresentable, not
validated.** Under D-01 and D-03 there is no feedback marker separate from the edge itself: an
edge is a feedback edge exactly when `from === to`. There is no second source of truth that could
disagree, so the correct response to that clause is to keep it that way and prove it with a test,
not to invent a marker so it can then be validated. Record this in the SUMMARY as the disposition
of that clause.
