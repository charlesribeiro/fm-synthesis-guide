## Why Algorithm 1 and Algorithm 32 are the tracer pair

A tracer must be falsifiable. A one-row tracer is not: a `getOperatorRole` implementation that
unconditionally returns `'carrier'` would pass a suite built only on Algorithm 32, and one that
mishandles self-loops would pass a suite built only on Algorithm 1. The pair is the minimum that
can fail:

| Algorithm | Carriers | Feedback op | Branch it exercises |
|---|---|---|---|
| 32 | 1, 2, 3, 4, 5, 6 | 6 | Operator 6 is a **carrier that also carries the feedback self-loop**. This is the fixture that catches RESEARCH.md Pitfall 1 — the self-loop must be excluded from "does this operator modulate another operator". It is also the empty-edge-list case: zero inter-operator edges. |
| 1 | 1, 3 | 6 | Operator 6 is a **modulator that also carries the feedback self-loop**, and the row has a mixed carrier/modulator population. Proves the `'modulator'` branch is reachable. |

Both rows are HIGH confidence in RESEARCH.md § Routing Reference Table (triangulated across
three independent sources), and both are the algorithms LESSON-01 and LESSON-02 will teach.
The remaining thirty rows are added in Plan 02-04 — this plan is not a reduced-scope version of
the dataset, it is the architectural slice the dataset gets built on.
