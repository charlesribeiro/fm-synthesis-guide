<objective>
Wire a real DX7-style four-rate/four-level envelope generator through every layer
of the engine — parameter model, DSP kernel, worklet message contract, worklet
processor, and the Angular audio adapter — so a played note is shaped by six
independent per-operator envelopes instead of one global voice ramp.

Purpose: this phase's change is atomic in TypeScript terms. The flat single-level
stand-in on `OperatorParameters` widens into a structured envelope, and every
consumer of that field has to move with it in the same commit or the tree does
not compile. Proving the whole path — including the note-lifecycle message the
kernel has never had — before building out the exhaustive proof surface means an
architectural mistake surfaces after one commit rather than after four plans.

Output: a live, envelope-driven six-operator worklet engine where note-on starts
six independent attack segments, note-off releases them from wherever they sit,
velocity still scales loudness, and the app is silent at rest.
</objective>

**2. `src/app/domain/dx7/audio/value-conversion.ts` — the rate curve (Claude's Discretion, informed by research).**

Add and export `ENVELOPE_MIN_FULL_SCALE_SECONDS` at `0.002` and `ENVELOPE_MAX_FULL_SCALE_SECONDS` at `6.4`, and `envelopeRateToLevelUnitsPerSample(rate: number, sampleRate: number): number`. The function normalises the rate across the rate range, interpolates the full-scale segment duration geometrically between the two endpoints — maximum duration raised to the complement, minimum duration raised to the normalised rate, expressed as maximum times the ratio of minimum to maximum raised to the normalised rate — and returns the level range divided by that duration times the sample rate. Clamp a non-finite or out-of-range rate into the rate bounds before use, treating a non-finite value as the minimum rate. Validate that `sampleRate` is finite and strictly positive, falling back to a documented default when it is not, so this function can never emit `NaN`, `Infinity`, zero or a negative speed onto the render thread for an invalid sample rate, while preserving the existing rate clamping and safety guarantee.

Document why this shape was chosen over reproducing the DX7's real asymptotic-exponential and quadratic hardware curves: an asymptotic model never reaches its target in finite time and needs an arrival epsilon that makes segment-transition timing non-deterministic and untestable, whereas a constant per-sample increment recomputed whenever a segment's target changes gives an exact closed-form sample count for any rate-and-distance pair while still being audibly non-linear, because the level it produces is converted to amplitude through the existing squared curve on every sample. Record the calibration anchor: the geometric interpolation puts rate 50 at roughly one hundred and nine milliseconds full scale, which is where the cited hardware measurement of a rate-50 decay time constant lands when carried out to the five time constants this codebase already treats as "fully decayed". State plainly, as the file's head comment already does for its siblings, that these are approximations and not a reproduction of the DX7's log-domain tables.

**3. `src/app/domain/dx7/dsp/envelope-generator.ts` — NEW (D-01, D-04).**

Open with the same header framing `operator.ts` uses: zero Angular imports enforced by the domain-purity gate, every formula independently unit-testable in Node with no browser and no jsdom Web Audio surface, and an explicit statement that this is an original implementation written from first principles toward DX7-style behaviour, never a transcription of or derived from any DX7 or Dexed source, and that it must never be described as an exact DX7 emulation.

Export `class EnvelopeGenerator` with `constructor(sampleRate: number, envelope?: Dx7Envelope)`. Validate the sample rate with the same `RangeError`-with-interpolated-received-value helper shape `operator.ts` uses. Allocate one `Float64Array(ENVELOPE_SEGMENT_COUNT)` in the constructor to hold the per-segment per-sample step derived from each rate, and never allocate again.

Private mutable instance fields, mirroring `operator.ts`'s persistent-field pattern: the current level on the DX7 0-99 scale starting at the minimum level, the current segment index starting at `RELEASE_SEGMENT_INDEX`, a held flag starting false, and an explicit idle flag starting true so never-gated rest is distinct from an active release tail. Starting in the release segment at level zero is the held-progression default; silence at rest is the idle flag, not "idle at the envelope's release target".

`setEnvelope(envelope: Dx7Envelope): void` stores the envelope and refills the precomputed step array from `envelopeRateToLevelUnitsPerSample`. It must not touch the current level or the segment index — a live parameter edit during a held note re-targets the envelope without restarting it, which is what keeps a slider drag from popping (D-04).

`gateOn(): void` sets the held flag, clears idle, and sets the segment index to the first segment. `gateOff(): void` clears the held flag, clears idle, and sets the segment index to `RELEASE_SEGMENT_INDEX`. Neither touches the current level. Document this as a deliberate divergence from `operator.ts`'s `resetPhase` reset pattern, citing D-04: a note released mid-attack or retriggered mid-release must move from its actual current level at the new segment's rate, so assigning a fixed starting value here is precisely the bug this design exists to prevent.

`render(output: Float32Array): void` writes exactly `output.length` per-sample amplitude values and allocates nothing. While idle, write `0` for every sample regardless of the release target, so a never-gated generator stays silent even when `levels[3]` is non-zero. After a note has been gated, preserve release-tail rendering: per sample, in this order: read the current segment's target level and precomputed step; move the current level toward the target by at most the step, clamping exactly at the target so the level can never overshoot; guard the level with the same treat-as-safe convention `operator.ts` applies to its inputs, resetting a non-finite level to the minimum level; while the generator is held and the segment index is below the release segment's predecessor and the current level equals that segment's target, advance the segment index — a bounded loop of at most two further advances, so an envelope whose consecutive targets are identical settles immediately instead of spending one sample per zero-distance segment; then write `outputLevelToAmplitude(currentLevel)` into the output slot — **except** when the generator is not held, the segment index is `RELEASE_SEGMENT_INDEX`, and the current level has reached that segment's target: write `0` instead, unconditionally, even if that release target (`levels[3]`) is itself non-zero (this is the must_haves prohibition against droning with no note held, made mechanical here — see that section for the full rationale). The target-reached check and the segment advance must happen once per sample inside this loop, never once per block: at the fastest rates a full-scale segment completes in under a hundred samples, so a per-block check would hold a stale target for most of a render quantum and structurally violate the "segment transitions match the modeled state machine" success criterion.

Note explicitly in the class doc that the third segment's target is the de-facto sustain plateau: once it is reached while the note is held there is nothing further to advance to, and the generator simply holds there; and that the release segment is entered only by `gateOff`, from whatever level is current, regardless of which segment was active.

Create `envelope-generator.spec.ts` in the same commit covering, at minimum, the behaviours listed in this task's behavior block for the generator: never-gated silence, the held progression through all three segments to the sustain plateau, the zero-distance settle, and one gate-off-mid-attack continuity case. Task 2 expands this file into the full invariant suite; do not pre-empt it here beyond these cases.
