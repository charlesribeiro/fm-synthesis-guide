<design_decisions>
Decisions this plan makes inside CONTEXT.md's "Claude's Discretion" area. The executor implements
these as written rather than re-deciding them.

**Facade location — `src/app/state/instrument-state.ts` (new directory).**
`docs/ARCHITECTURE.md` lists "Application state" as layer 2, distinct from layer 3 "Browser
adapters" — which is what `src/app/core/` currently holds (`core/audio`, `core/browser`, both DI
seams to browser APIs, as README's source-tree comment states). Instrument state is not a browser
seam. Phases 5, 6, and 12 add three more facades (audio lifecycle, lesson/progress, settings), so
`src/app/state/` is their shared home. `03-PATTERNS.md` marked this path explicitly as Claude's
discretion.

**One private patch signal, not three.**
State is a single `WritableSignal<InstrumentPatch>` holding `{ algorithmId, operators, feedback }`,
with each public per-field selector exposed as a `computed()` over it. The public read-only surface
is exactly what `03-PATTERNS.md` describes; only the private storage is unified. Rationale: D-03's
A/B snapshot must capture the whole patch atomically and restore it exactly — with three
independent signals a snapshot is a manual re-assembly that can drift. `computed()` applies Object.is
equality to its output, so a change to one operator does not notify consumers of `algorithmId`.

**Selected operator is NOT tracked here.**
CONTEXT.md leaves this to the planner. STATE-01 names only selected algorithm, operator parameters,
and feedback level. A focused/edited operator is view state; Phase 4 owns it locally. No seam is
stubbed for it — adding one later is a pure addition to this class, not a breaking change.

**Invalid command input throws.**
`setAlgorithm`, `setFeedback`, and `updateOperator` validate and throw `RangeError` on
out-of-range input rather than clamping. This matches the codebase's existing validation posture
(`validate-algorithm.ts` throws `InvalidAlgorithmError`) and CLAUDE.md's "validate external data at
boundaries". Callers that need forgiveness (a future MIDI CC source) clamp before calling. See the
flagged assumptions in frontmatter — this is a planner judgement, not a spec-confirmed rule.

**Default algorithm id is 1.**
D-11 pins every numeric patch value but not which algorithm is selected on first load. Algorithm 1
is the dataset's first row and the algorithm ROADMAP Phase 6 / LESSON-02 teaches as the canonical
modulation stack. Reversible: a one-line constant change.
</design_decisions>
