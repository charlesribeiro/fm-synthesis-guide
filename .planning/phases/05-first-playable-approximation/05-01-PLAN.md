<phase_decisions>
Discretion calls locked here so later plans do not re-litigate them:

- **`'enabling'` is component-local, not a fifth `AudioEngineStatus`.** `05-UI-SPEC.md` refers to
  a `status()` value of `'enabling'`, but `AudioEngineStatus` (Phase 1, shared with Phase 7's
  AudioWorklet engine) has exactly four members: `'unavailable' | 'suspended' | 'ready' |
  'error'`. Widening that union would change a cross-phase contract to express a purely visual
  in-flight state. Playground instead owns a private `enabling` signal set while the
  `initialize()` promise is pending. `synth-engine.ts` is NOT modified by this phase.
- **`note` is a MIDI note number validated against 0..127, not against the 12-key range.** D-07's
  fixed C4–B4 octave is a property of the play surface, not of the engine; Phase 6's lessons will
  drive the same engine outside that octave. Widening the playable range later must be a UI
  change only.
- **`velocity` is MIDI-style, 1..127.** The `SynthEngine` interface leaves the unit unspecified;
  this fixes it consistently with `note`.
- **Retrigger and release are scheduled on the audio clock, never with `setTimeout`.** Every
  transition is expressed as `AudioParam` automation at `currentTime + offset`, so there is no
  timer to leak and every transition is deterministically assertable in a spec.
</phase_decisions>

**`src/app/core/audio/web-audio-synth-engine.ts` (new).** `@Injectable({ providedIn: 'root' })
export class WebAudioSynthEngine implements SynthEngine`. Inject `AUDIO_CONTEXT_CTOR`,
`InstrumentState`, and `DestroyRef`. Private `_status = signal<AudioEngineStatus>(...)` seeded
`'unavailable'` when the injected constructor is `null` and `'suspended'` otherwise, exposed as
`readonly status: Signal<AudioEngineStatus> = this._status.asReadonly()` (never a plain writable
signal, never a getter). Hold the context and every node as private class fields — CLAUDE.md
forbids storing an `AudioNode` or the context in signal state.

The constructor does exactly two things: register `destroyRef.onDestroy(() => this.destroy())`,
and register one `effect()` that reads `instrumentState.algorithm()`, `instrumentState.operators()`
and `instrumentState.feedback()` into locals FIRST and only then returns early if the graph has not
been built yet. Reading all three signals before the early return is load-bearing: an effect that
returns before reading a signal never registers it as a dependency and will not re-run when it
changes. When the graph does exist the effect applies the read values imperatively. This is the
one sanctioned `effect()` in this phase — imperative synchronisation with an external system per
CLAUDE.md; never a `computed()` deriving graph shape.

`initialize()` is the only place `new ctor()` runs, and it is called only from a user-gesture
handler. Behaviour: return immediately if the constructor is `null` (leaving `'unavailable'`) or if
a context already exists (idempotent — a double activation must not build a second graph). Inside
a try/catch: construct the context; build the persistent graph; `await context.resume()`; apply the
current `InstrumentState` values; set `'ready'`. On any throw, tear down whatever was built, drop
the context reference, and set `'error'`.

The persistent graph, built once in `initialize()` and never rebuilt per note (this is the
lifecycle commitment that makes stuck voices structurally impossible — RESEARCH.md Pitfall 2):
one `masterGain` connected to `context.destination` with its gain set to `MASTER_GAIN`; one
`voiceGain` connected to `masterGain`, starting at zero, which is the ONLY node whose gain moves
for note transitions; and, for each of the six `OPERATOR_IDS`, an `OscillatorNode` of type
`'sine'` connected to its own `levelGain`. Start all six oscillators once, immediately. Track
started oscillators so `destroy()` can prove a one-to-one stop.

Routing in this task is deliberately the thin path: connect each carrier's `levelGain` (carriers
come from `deriveCarriers(instrumentState.algorithm())` — never a locally re-derived carrier test)
to `voiceGain`, and leave modulator `levelGain`s unconnected so modulators are silent. Set each
carrier's `levelGain.gain` from `outputLevelToAmplitude` of that operator's `outputLevel`.
Modulation-edge patching, the feedback `DelayNode`, and D-02's live re-patch are plan 05-02's
expansion of this same routing function — leave a single private routing method as the seam they
extend, but do not stub anything that would need the graph reshaped.

`noteOn(note, velocity)`: validate first, before touching any `AudioParam` — reject a `note` that
is not an integer within `MIN_MIDI_NOTE`..`MAX_MIDI_NOTE` and a `velocity` that is not an integer
within `MIN_VELOCITY`..`MAX_VELOCITY`, each with a `RangeError` in the exact field/range/received
message shape `operator-parameters.ts` uses (T-05-01). Then, if the graph is not built, return
silently. Compute the note frequency once via `midiNoteToFrequency`, schedule each oscillator's
`frequency` with `setValueAtTime` at the current time, and schedule `voiceGain.gain`:
`cancelScheduledValues(now)`, `setValueAtTime(currentValue, now)`, then
`linearRampToValueAtTime(velocityToAmplitude(velocity), now + ATTACK_SECONDS)`. Record the held
note in a private field. Define `ATTACK_SECONDS` and `RELEASE_TIME_CONSTANT` as named constants in
this file (15ms and 15ms respectively, per RESEARCH.md Assumptions Log A2 — tuned by ear in plan
05-04). Never assign `gain.value` for a note transition (RESEARCH.md Pitfall 4).

`noteOff(note)`: ignore the call entirely when `note` is not the currently held note — a stale
release from a superseded key must not silence the note now sounding. Otherwise
`cancelScheduledValues(now)`, `setValueAtTime(currentValue, now)`,
`setTargetAtTime(0, now, RELEASE_TIME_CONSTANT)`, and then `setValueAtTime(0, now +
RELEASE_SECONDS)` where `RELEASE_SECONDS` is a named constant equal to five time constants — the
exponential decay is what the ear hears as smooth, and the terminating hard-zero anchor is what
makes silence exact and assertable rather than asymptotic. Clear the held note.

`allNotesOff()`: same release schedule, unconditional. `setAlgorithm`, `updateOperatorLevel` and
`setFeedback` re-run the routing/level application against the current `InstrumentState` values
(they are fleshed out in 05-02). `destroy()`: run the immediate-silence path, `stop()` every
started oscillator, `disconnect()` every node created in `initialize()`, `close()` the context,
drop all node references, and set status back to `'suspended'` when a constructor is available (a
later `initialize()` may legitimately rebuild) or leave `'unavailable'` when it is not.
