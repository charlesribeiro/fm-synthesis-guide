<objective>
Prove the whole VIZ-01 path end to end on one thin slice: widen the hand-rolled
Web Audio boundary with an analyser, insert that analyser between the live
engine's master gain and the destination, expose it as plain data-copying read
methods, and drive a Canvas 2D oscilloscope from those reads on an injected
animation-frame loop that is embedded in Playground and touches no Angular
signal.

Purpose: every architectural risk in this phase lives on this one path — the
`AudioContextLike` widening D-02 rates costly, the exact insertion point that
silently breaks an existing spec helper, and the first component in this
repository that owns native DOM and an imperative per-frame loop. Proving all
three together on a single waveform, before any spectrum math or comparison UI
exists, means an architectural mistake surfaces after one commit rather than
after four.

Output: a Playground page where enabling audio and holding a note visibly moves
a real oscilloscope trace, with the spectrum lane, the A/B controls and the
randomizer still to come.
</objective>

**1. `src/app/core/audio/audio-context.token.ts` — widen the boundary (D-02).**

Add and export `AnalyserNodeLike extends AudioNodeLike` carrying exactly four members and nothing more: a writable `fftSize: number`, a `readonly frequencyBinCount: number`, `getByteTimeDomainData(target: Uint8Array): void`, and `getByteFrequencyData(target: Uint8Array): void`. Place it directly after `DelayNodeLike` and follow that declaration's comment style. Add `createAnalyser(): AnalyserNodeLike;` to `AudioContextLike` immediately after `createDelay`. Document in a short comment that `frequencyBinCount` is always half of `fftSize`, and that this is deliberately a fraction of the real node's surface — the smoothing and decibel-range members are omitted because nothing in this app tunes them, following the same just-what-the-app-needs rule `GainNodeLike` and `DelayNodeLike` already state.

**2. `src/app/core/audio/synth-engine.ts` — the analysis capability contract.**

Add and export `ANALYSER_FFT_SIZE` with value `2048` and `ANALYSER_FREQUENCY_BIN_COUNT` derived as `ANALYSER_FFT_SIZE / 2`. Document that 2048 is D-08's locked value, that it also happens to be the platform default, and that stating it explicitly is what makes the buffer sizes downstream provable rather than inherited.

Add and export `interface AnalysisTap` with exactly three members: `getAnalysisSampleRate(): number`, `readTimeDomainInto(target: Uint8Array): boolean`, and `readFrequencyInto(target: Uint8Array): boolean`. Document the contract precisely: both read methods copy into a caller-owned, caller-preallocated buffer and return `true` only when live data was written; a `false` return means there is no live tap right now and the buffer was left untouched. Document why these are plain methods rather than signals or a node accessor: they are polled from an animation-frame callback many times a second and must stay entirely off the signal graph, and handing out the node itself would put an audio node within reach of component state, which the project rules forbid outright.

Add and export `hasAnalysisTap(engine: SynthEngine): engine is SynthEngine & AnalysisTap`, a structural guard checking that both read methods and the sample-rate method are functions. Document that `AnalysisTap` is deliberately a separate capability rather than new required members on `SynthEngine`: the reference fallback engine is not the live path and is not being given a tap, so a component asks whether the engine it was handed can be analysed rather than assuming every implementation can.

**3. `src/app/core/audio/testing/fake-audio-context.ts` — the fake analyser (Pitfall 5).**

Add `FakeAnalyserNode extends FakeAudioNode implements AnalyserNodeLike` following the `FakeGainNode`/`FakeDelayNode` shape. Give it a writable `fftSize` defaulting to `2048`, a `frequencyBinCount` getter returning `fftSize / 2`, and two settable canned-data fields — one for time domain, one for frequency — each `Uint8Array | null` and `null` by default. Give it two call counters, one per read method.

`getByteTimeDomainData(target)` throws a `RangeError` naming both the expected and the received length when `target.length` is not equal to `fftSize`; otherwise it fills `target` from the canned time-domain array when one is set, and with the constant `128` — the byte value that means "at the zero crossing", so an unset fake reads as silence rather than as noise — when it is not. `getByteFrequencyData(target)` mirrors this exactly against `frequencyBinCount`, filling with `0` when no canned array is set. When a canned array is shorter than the target, fill the remainder with the same default. The length check is the whole point of this double: a hand-rolled fake that silently accepts any buffer would leave the one mismatch that actually throws in a real browser completely unexercised.

Add a `createdAnalysers: FakeAnalyserNode[]` registry field alongside `createdGains`, a `createAnalyser(): FakeAnalyserNode` method following `createGain`'s exact three-line shape, and widen the `createdNodes` getter and its return type to include the analysers so the existing teardown-assertion specs cover the new node type automatically.

**4. `src/app/core/audio/worklet-synth-engine.ts` — insert the tap and expose the reads (D-02, D-08).**

Add `analyser: AnalyserNodeLike | null` to `BuiltWorkletGraph` alongside `masterGain`, and initialise it to `null` in the same literal that already initialises `masterGain: null`. Add a matching `private analyser: AnalyserNodeLike | null = null` instance field next to `private masterGain`, and assign it from the built graph in the same place `this.masterGain = built.masterGain` already happens.

In the graph-construction method, immediately after the master gain is created, create the analyser, set its `fftSize` from `ANALYSER_FFT_SIZE`, and change the connection chain so the worklet node still connects to the master gain, the master gain then connects to the analyser, and the analyser connects to the context destination. Assign it onto the built graph next to `built.masterGain`. Add a comment stating that the analyser is a read tap on the final mix and passes audio through unmodified, so inserting it changes what can be observed and nothing about what is heard.

In the discard path that cleans up a graph an interrupted initialization never committed, add an optional-call disconnect of the built graph's analyser next to the existing master-gain disconnect. In the teardown method, add the same optional-call disconnect of the instance field next to the existing master-gain disconnect, and null the field alongside the others.

Declare the class as also implementing `AnalysisTap` and add the three methods. `getAnalysisSampleRate()` returns the context's `sampleRate` when a context exists and `0` otherwise. `readTimeDomainInto(target)` returns `false` immediately when the analyser field is null **or** when there is no active voice (`voiceActive === false`) — initialization alone is not live audio — and otherwise calls the node's time-domain getter with the caller's buffer and returns `true`; `readFrequencyInto` mirrors it. Track graph/voice activity separately from the key-held state: `noteOn` sets `heldNote` and `voiceActive`; `noteOff` clears `heldNote` only, so reads continue through the envelope release; `destroy` (and any teardown that discards the graph) clears both so a visualizer after `initialize()` without an active voice receives no-live-data and draws rest. Add a regression covering reads after `noteOff` that observes release samples before the tap becomes inactive. Do not validate the buffer length here: the boundary type and the fake both enforce it, and adding a third check would be a fourth place for the size convention to drift.

**5. `src/app/core/audio/worklet-synth-engine.spec.ts` — repair the helper the insertion breaks (Pitfall 1).**

Add a short `findAnalyser` helper next to it so the new tests in this task and in task 2 share one lookup. Leave every existing call site and every existing assertion otherwise untouched: the point of this repair is that the gain-scheduling tests keep testing gain scheduling.

Add the analyser-specific cases from this task's behavior block: the connection chain, the fft size and bin count, the pre-initialize `false` returns, and the post-initialize `true` returns copying canned data.

**6. `src/app/core/browser/animation-frame.token.ts` and `canvas-2d.token.ts` — the two new browser seams (D-03).**

Both files follow `motion-preference.ts`'s `MATCH_MEDIA` precedent exactly: a minimal interface, a root-provided injection token, a factory that feature-detects the global without touching it at module scope, and a graceful no-op fallback rather than a thrown error when the global is missing.

In `animation-frame.token.ts` export `interface AnimationFrameScheduler` with `request(callback: (timestampMs: number) => void): number` and `cancel(handle: number): void`, and `ANIMATION_FRAME_SCHEDULER` as a root-provided `InjectionToken<AnimationFrameScheduler>` whose factory returns an implementation delegating to the browser's frame-request and frame-cancel globals when both are callable, and otherwise a scheduler whose request returns `0` and whose cancel does nothing. **7. `src/app/core/browser/testing/` — the two fakes.**

`fake-animation-frame-scheduler.ts` exports `FakeAnimationFrameScheduler implements AnimationFrameScheduler`: `request` stores the callback against an incrementing handle and returns it; `cancel` records the handle in a public `cancelledHandles` array and removes any pending callback for it; a public `pendingCount` getter reports how many callbacks are outstanding; a public `tick(timestampMs: number): void` drains the currently-pending callbacks once, invoking each with the given timestamp, so a callback that re-requests during the tick is not re-invoked within the same tick. `fake-canvas-2d-context.ts` exports `FakeCanvas2dContext implements CanvasRenderingContext2DLike`: every method pushes a record onto a public ordered `calls` array carrying the method name and its arguments, and every writable property is a plain field. The template renders a section with an accessible heading, one canvas element carrying the template reference, an image role and a label naming it as the oscilloscope, and a paragraph of description text derived from the engine status by a `computed` — one string for the ready case describing that the trace shows the live waveform of the sounding note, and one for every non-ready case saying the display is flat because no audio is running. The description changes only when the status changes; it must never be updated from the frame callback. Give the canvas a stable class and set its CSS box size in the stylesheet from the same nominal dimensions the constants state, keeping the backing-store sizing and the CSS sizing in agreement. The stylesheet follows `play-surface.scss`'s posture: an embedded region, no page-layout mixin, colours and spacing from the existing custom properties only.
