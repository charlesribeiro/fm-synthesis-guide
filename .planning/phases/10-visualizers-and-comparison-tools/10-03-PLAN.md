<objective>
Build the constrained-randomization half of VIZ-02: a pure domain function that
walks every numeric field of an instrument patch by a bounded random delta from
its current value and clamps it to that field's declared range, and a new
`InstrumentState` command that funnels the result through the existing
validators before a single atomic write to the live patch.

Purpose: this is the only genuinely new state-mutation path in the phase, and
the one place a quiet arithmetic mistake could put an out-of-range value into
the patch every other layer trusts. Isolating the delta and clamp math into a
pure, Angular-free module makes it testable to the boundary value, and routing
every field back through the validators the existing commands already use turns
a future drift between the walk's bounds and the domain's bounds into a thrown
error instead of a silent corruption.

Output: `InstrumentState.randomize()` — a validated, immutable, single-write
command that plan 10-04 wires to a button.
</objective>

Export `type RandomSource = () => number`.

**`randomWalkInteger(current, min, max, deltaFraction, rng)`.** Read one value from the source; when it is not a finite number in the closed unit interval, substitute the midpoint so the delta becomes zero. Map the source value onto the symmetric interval from minus one to plus one, multiply by the delta fraction and by the field's full width, round to the nearest integer, add to the current value, and clamp into the bounds. Return an integer. Document that rounding after scaling — rather than scaling a rounded value — is what makes the two extreme source values reach exactly the full delta in both directions, which is the property the spec pins.

**`randomWalkRatio(current, rng)`.** Find the current value's position in the frozen coarse-ratio list; when it is absent, use the position of the numerically nearest member, so a value that arrived from outside this module cannot make the walk throw. Compute an integer position delta by the same scaled-and-rounded rule applied to the list's last index, clamp the resulting position into the list, and return the member at that position. Document that walking the position rather than the value is mandatory: the validator rejects any ratio absent from this frozen list, so interpolating between two members would produce a value that fails validation at the state boundary.

**`randomWalkFixedFrequencyHz(current, rng)`.** Clamp the current value into the randomization-local range first, substituting the floor when it is not a positive finite number. Multiply it by a factor of one plus the same symmetric scaled source value times the delta fraction, clamp the product back into the range, and round to two decimal places. Document why this walk is multiplicative where every other field's is additive: frequency is perceived logarithmically, so a fixed proportion of the current value is the musically meaningful step, and there is in any case no declared upper bound on this field from which a linear fraction could be taken.

**`randomWalkOperatorParameters(current, rng)`.** Return a new operator parameters object. Copy `enabled` and `mode` straight through — never walked, per D-16, because a two-value flag has no bounded-walk meaning and because flipping either is a structural change rather than a nudge, the same reason D-12 gives for excluding routing. Walk `ratio` only when the mode is ratio and copy it otherwise; walk `fixedFrequencyHz` only when the mode is fixed and copy it otherwise. Walk `outputLevel` and `detune` against their imported bounds. Build a new envelope object whose four rates and four levels are each walked independently against the imported rate and level bounds — eight separate source reads, not one delta applied eight times, because a single shared delta would move the whole envelope rigidly and lose the per-segment variety that makes randomizing useful.

**`randomWalkPatch(patch, rng)`.** Build a new operators record by walking each of the six operators in the fixed operator-id order, walk the feedback depth against its imported bounds, and return a new patch object carrying the input's `algorithmId` unchanged. Never write into the input or any object reachable from it. Document that the snapshot slots hold direct references to previously-current patch objects rather than clones, so immutability here is what keeps a captured A or B slot exact.

**Spec.** Cover every case in this task's behavior block. Build a small deterministic source helper that yields values from a fixed cycling list, and a second that yields a linear sweep, and drive the thousand-iteration invariant cases from both plus the two extremes so the proof is not accidentally limited to a narrow slice of the source's output. Assert the domain-validator invariant by actually calling `validateOperatorParameters` and `validateFeedbackLevel` inside the loop rather than by re-checking bounds in the spec, so the proof is against the real validators and cannot drift from them.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Computed randomization → patch signal | The only new state-mutation path in this phase. The "input" is internally computed rather than externally supplied, which is exactly why it is easy to trust it without checking. |
| Patch signal → live worklet | A partially-written or out-of-range patch reaches the audio render thread through the existing engine effect; there is no second gate downstream. |
| Current patch ↔ captured snapshots | The A/B slots hold direct references to prior patch objects; any in-place mutation on the randomization path would silently rewrite a slot's contents. |
