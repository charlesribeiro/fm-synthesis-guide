<objective>
Add the pure grouping transform that turns the flat lesson dataset into the four curriculum sections the
`/learn` index will render, in the order D-02 fixes, with the labels and one-line descriptions that make
"grouped by recurring structure, not rote memorisation" visible rather than implied.

This plan builds no UI. It exists in wave 1, alongside the tracer, because the transform is a
self-contained pure function whose correctness does not depend on how many lesson rows exist yet — it is
specified and tested against fixtures and against whatever the live dataset currently holds, and plan
11-05 consumes it once all thirty-two rows are in place.

Purpose: satisfy D-01 and D-13's data half — the grouping must be a data transform, because CLAUDE.md
requires algorithm topology to be data and never hardcoded template layout, and grouping by teaching tag
is topology.
Output: one new domain module and its spec.
</objective>

**Module header.** State that curriculum grouping is a data transform rather than template layout, per
CLAUDE.md's rule that algorithm topology is data and never hardcoded template layout, and that a lesson's
curriculum group is read from the canonical dataset's own `teachingTags` (D-01) rather than restated in
lesson data or in a template.

**`CURRICULUM_GROUP_ORDER`.** A frozen `readonly TeachingTag[]` holding `parallel`, `additive-stacks`,
`tree-branch`, `rooting`, in that order. Document that this is D-02's reordering: the dataset's own
`TEACHING_TAGS` array lists additive stacks first, but the curriculum opens with the Parallel group
because Algorithm 32's lesson — the simplest possible case, no modulation at all — is the curriculum's
opener and Phase 6 already built it, with Algorithm 1's Additive Stacks group second for the same
reason. Note that the four members must remain a permutation of `TEACHING_TAGS` and that a spec asserts
it, so a group added to the taxonomy cannot silently go unplaced.

**`CURRICULUM_GROUP_LABELS` and `CURRICULUM_GROUP_DESCRIPTIONS`.** Two frozen records keyed by
`TeachingTag`, mirroring `TRY_THIS_PARAM_LABELS`'s convention in `lesson-definition.ts` — the one place a
component may read a display name, so no template hardcodes it. Labels are short headings; descriptions
are one original sentence each naming the recurring routing shape that group's algorithms share, written
from the taxonomy this repository already owns and naming no third-party product or manual. Both records
are total over `TeachingTag` with no index signature, so adding a tag to the union without adding its
label is a compile error rather than an undefined heading.

**`LessonGroup`.** An interface with readonly `tag: TeachingTag`, `label: string`, `description: string`
and `lessons: readonly LessonDefinition[]`.

**`groupLessonsByTeachingTag(lessons: readonly LessonDefinition[], algorithms: readonly
AlgorithmDefinition[]): readonly LessonGroup[]`.** Build a lookup from algorithm id to algorithm row from
the passed `algorithms`. Walk `lessons` once in input order, resolving each lesson's algorithm row and
raising a `RangeError` naming the lesson's `algorithmId` when the row is absent, and a `RangeError`
naming the algorithm's id when its `teachingTags` array is empty — mirroring `getLesson`'s
validate-or-throw posture and its template-literal message style, because a lesson silently missing from
every group is a failure a learner would experience and no test would report. Append each lesson to its
tag's bucket, which preserves input order within a group by construction and needs no sort. Then map
`CURRICULUM_GROUP_ORDER` to the four `LessonGroup` objects, taking each group's label and description
from the two records, freezing each `lessons` array, each group object and the returned array.

Document that the function is total over `CURRICULUM_GROUP_ORDER` — all four groups are returned even
when a group has no lessons — so its output shape does not depend on how many lesson rows exist, and
that plan 11-04 separately asserts every group is non-empty for the shipped thirty-two-row dataset.

**Spec.** Cover every case in this task's behavior block. Build small fixture lessons and fixture
algorithms named by pedagogical intent rather than reusing the live datasets for the structural cases,
and add live-dataset cases that hold at any row count: every returned lesson's algorithm row carries its
group's tag, and the concatenation is a permutation of `LESSONS`. Assert freezing with `Object.isFrozen`
at all three levels.
