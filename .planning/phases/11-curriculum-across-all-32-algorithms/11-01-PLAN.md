<objective>
Build the structural machinery that turns a canonical algorithm row into a lesson starting patch and a
try-this experiment, then prove it end to end by shipping the Parallel group's six new lessons
(Algorithms 26 through 31) through it.

This is the phase's tracer. Everything downstream — the eleven rows in plan 11-03, the thirteen rows in
plan 11-04, the grouped index in plan 11-05 — reuses exactly the module surface this plan establishes.
If the derivation rules (D-04 through D-08) or the try-this selection rule (D-11) are wrong, they are
wrong here, after six rows, not after thirty.

Purpose: satisfy CURR-01's "original preset" and "experiment" halves with rules rather than with 180
hand-picked constants, and lock the curriculum ordering (D-02, D-03) that every later plan appends into.
Output: two new domain modules with dedicated specs, one new lesson row factory, six new `LESSONS` rows,
and a `LESSON_IDS` list grown from two members to eight.
</objective>

<flagged_assumptions>
The deterministic edge probe ran against CURR-01's requirement text and returned three probes, all
`unresolved` — no probe classified as covered or backstopped. All three are surfaced here rather than
dropped, with the concrete position this plan takes on each. None of the three is force-fitted into a
machine-checkable acceptance criterion it does not naturally support.

- **`adjacency` — "when two things are exactly equal or just touch, do they merge, collide, or
  separate?"** Unresolved by the requirement text. Concretely, this phase's version of the question is
  the duplicate-topology clusters `11-RESEARCH.md` identified: Algorithms 1/13/14, 3/4/11 and 24/25/31
  are pairwise identical in both edges and feedback operator, so a structure-only builder produces
  identical presets for every member of a cluster. This plan's position: they stay **separate** lessons
  with byte-identical generated presets, and the prose says so honestly rather than manufacturing a
  difference. The three-way clusters land in plans 11-03 and 11-04; this plan carries no cluster member,
  but establishes the builder whose determinism makes the equality exact and testable.

- **`empty` — "what is the result for empty, single-element, or null input?"** Unresolved by the
  requirement text. Concretely: `getFeedbackOperator` returns `null` for an algorithm with no self-loop,
  and an algorithm could in principle have no modulators at all. `11-RESEARCH.md` Pitfall 1 confirms
  every one of the thirty-two dataset rows declares exactly one self-loop, so the null-feedback branch is
  unreachable against today's data. This plan's position: implement both branches defensively and
  document them as unreachable, and do **not** author an acceptance criterion asserting any shipped row
  has zero feedback — that criterion would fail against a correct implementation. Algorithm 32's own
  hand-authored lesson is the single-element-shaped case (no modulators at all) and is untouched here.

- **`ordering` — "when elements compare equal, is output order specified and stable?"** Unresolved by
  the requirement text. Concretely, two orderings in this plan need a stated tie-break: which operator
  the try-this rule picks when several modulators sit at the same maximum hop depth, and which isolated
  carrier it picks when several exist. Both are specified below (prefer the feedback operator when it is
  among the deepest, else lowest operator id; lowest operator id among isolated carriers) and both are
  asserted by the cross-check spec, so the rule is deterministic rather than dependent on edge-array
  declaration order.
</flagged_assumptions>

**`src/app/domain/dx7/models/hop-distance.ts` (new).** Pure, no Angular import, sitting beside
`derive-role.ts` because hop distance is a structural graph fact about an algorithm, not a lesson
concern. Import only `OPERATOR_IDS`/`OperatorId` from `./operator`, `AlgorithmDefinition` from
`./algorithm-definition`, and `getOperatorRole` from `./derive-role`.

Export `hopDistanceFromOutput(algorithm: AlgorithmDefinition, operatorId: OperatorId): number`. A
carrier returns `0`. Otherwise collect the operator's outgoing edges excluding its own self-loop —
`edge.from === operatorId && edge.to !== operatorId`, the same guard `getOperatorRole` already uses and
for the same reason — recurse into every target, and require every target's hop distance to be equal;
raise a `RangeError` naming the operator and the disagreeing depths when they are not, rather than
reading the first edge (`11-RESEARCH.md` Pitfall 5). Return one more than that agreed depth. Carry an
internal visited-operator set through the recursion and raise a `RangeError` naming the operator when an
operator is re-entered, so a cyclic edge list fails loudly instead of exhausting the stack (threat
T-11-03); document that the shipped dataset's edges always run from a higher operator id to a lower one,
which is why the guard never fires against real data. Follow `derive-role.ts`'s message style: a
template literal naming the offending value, no interpolation of whole objects.

Export `maxModulatorHopDistance(algorithm): number` returning the largest hop distance over the
algorithm's modulators, or `0` when it has none, and `deepestModulators(algorithm): readonly
OperatorId[]` returning the modulators at that maximum in ascending id order by filtering
`OPERATOR_IDS`, mirroring `deriveCarriers`'s filter-the-fixed-array style so declaration order in
`edges` can never affect the result.

**`src/app/domain/dx7/models/derive-role.ts` (extend).** Add
`deriveIsolatedCarriers(algorithm): readonly OperatorId[]` — the carriers with no incoming modulation
edge from another operator, i.e. filter `OPERATOR_IDS` for operators whose role is `carrier` and for
which no edge satisfies `edge.to === operatorId && edge.from !== operatorId`. Document that an isolated
carrier is a bare unmodulated partial, structurally identical to one of Algorithm 32's six operators,
and that the `edge.from !== operatorId` conjunct is load-bearing for the same reason
`getOperatorRole`'s mirror-image conjunct is: a feedback self-loop must not count as incoming
modulation. Do not change any existing function in this file.

**`src/app/domain/dx7/lessons/structural-lesson-patch.ts` (new).** Pure, no Angular import.

Export `SHARED_MODULATOR_ENVELOPE`, a `Dx7Envelope` frozen at every level with rates `[80, 16, 16, 55]`
and levels `[99, 70, 40, 0]` — the exact values `lessons.ts`'s module-local
`ALGORITHM_1_MODULATOR_ENVELOPE` carries today, promoted to one shared exported constant so D-05's "one
single shared envelope shape" is literally one object rather than two identical ones that could drift.
Carry over that constant's existing documentation (why rate 16 takes the 99-to-40 drop roughly one
second under the geometric rate curve, and why a held note therefore opens bright and audibly mellows),
and add that it now serves every modulator in every lesson including Algorithm 1's.

Export the named constants `CARRIER_OUTPUT_LEVEL` at `75`, `MODULATOR_BASE_OUTPUT_LEVEL` at `60`,
`MODULATOR_OUTPUT_LEVEL_STEP` at `5`, `SHARED_FEEDBACK_LEVEL` at `3`, `MIN_ADDITIVE_LIKE_CARRIERS` at
`4` and `MIN_ADDITIVE_LIKE_ISOLATED_CARRIERS` at `2`. Document `SHARED_FEEDBACK_LEVEL` as mid-scale on
the `MIN_FEEDBACK_LEVEL`..`MAX_FEEDBACK_LEVEL` range imported from `patch.ts`, matching Algorithm 1's
existing hand-authored value so the self-loop is reliably audible (D-08), and explicitly as a fixed
value applied uniformly rather than a per-algorithm tuning knob.

Export `structuralOutputLevel(role: OperatorRole, hopDistance: number): number`: a carrier returns
`CARRIER_OUTPUT_LEVEL`; a modulator returns `MODULATOR_BASE_OUTPUT_LEVEL` minus
`MODULATOR_OUTPUT_LEVEL_STEP` times one less than its hop distance, clamped into
`MIN_OUTPUT_LEVEL`..`MAX_OUTPUT_LEVEL` imported from `operator-parameters.ts`. Document that this
reproduces the descending-by-hop shape Algorithm 1's hand-authored chain already uses — carriers well
above modulators, each chain step one notch quieter than the one closer to output — structurally rather
than verbatim (D-06), and that the deepest operator in the whole dataset sits at hop four, which lands
on `45` and never approaches the clamp.

Export `isAdditiveLikeAlgorithm(algorithm): boolean` — D-07's ratio exception expressed as a structural
predicate over the algorithm's own graph rather than a hand-maintained id list. It is true when all
