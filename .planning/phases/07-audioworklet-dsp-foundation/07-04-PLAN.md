<objective>
Close the single failing must-have from 07-VERIFICATION.md: the dev listening harness can reach a
production build.

Purpose: 07-03 declared that "the harness ships nothing to production" and proved it only for a
clean checkout. Verification reproduced, twice and deterministically, that the realistic sequence
the README itself documents — `npm run harness`, then later a plain `npm run build` with no manual
cleanup — copies `worklet-harness.js` and `worklet-harness.html` into
`dist/dx7-algorithm-lab/browser/dev/`, reachable at a direct URL. The root cause is structural: the
harness wrote into `public/`, and the asset configuration copies that entire tree verbatim. The
previous guarantee rested on a convention (never pass the flag from a lifecycle hook) rather than on
structure, and a convention cannot survive a stale directory.

This plan moves the harness output out of the production asset root entirely, gives it a named
development-only route back to its original URL so D-06's instrument keeps working, and installs an
automated gate that runs the failing sequence itself.

Output: a relocated harness build output, a harness build/serve configuration, two verification
scripts, npm wiring, a corrected README, and updated validation records.
</objective>
